How to read a lab

Design

Switches which kit's tokens and ornament the frame resolves against. Nothing in the markup changes — that is the point of the theme engine.

Viewport

390 is the phone the site is designed for. The type ramps with the frame, not the browser window, so 768 and 1240 show the real scale change.

The wall label

Under each frame: the route, the capability, the entitlement, and two or three specific things worth checking on that scene.

Placeholders

Every TODO(Tyler & Sara) is a fact only the couple can supply — an engraved blank plate in Gilded Hour, an unfilled specimen tag in Conservatory. Never invented copy.

Testing the real thing

These labs are static harnesses — no database, no capability pipeline, no server-side authorization. They are for judging the interface. To exercise the actual system:

npm run dev          # localhost:3000, auto-migrates and seeds PGlite
npm run verify       # typecheck, lint, unit, stylelint, design lint,
                     # detector, integration on PGlite, build
npm run test:e2e     # Playwright, needs BASE_URL

The labs are regenerated from the shipped tokens and art, so they cannot drift silently:

npm run design:sync && node docs/prototypes/build.mjs

Facts on every lab come from docs/design/brief.md and src/content/seed/*. Guest data is the committed fictional fixtures — Testhouse, Fixture and Solo — because real guest data never enters the repository.
